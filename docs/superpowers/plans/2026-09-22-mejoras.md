# Plan de implementación — Mejoras 2026-09 (docs/MEJORAS.md N-01…N-28)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cerrar los hallazgos de `docs/MEJORAS.md` en el orden de ataque acordado, dejando la app segura (escrituras en servidor, RLS, admin con rol), sin los bugs funcionales detectados y con red de seguridad (typecheck, tests, CI).

**Architecture:** Toda escritura pasa por endpoints Astro (`src/pages/api/*`) que usan el service role y validan con Zod; el navegador solo lee. `current_amount` lo recalcula un trigger en Postgres a partir de las contribuciones `completed`; el backoffice confirma pagos y aprueba mensajes. Realtime pasa de `postgres_changes` sobre toda la tabla a *broadcast* por proyecto emitido desde triggers (sin PII, sin fuga entre proyectos). Migraciones versionadas en `supabase/migrations/`.

**Tech Stack:** Astro 5.18 (SSR, adapter node), React 19.3, @supabase/supabase-js 2.117, Zod 3, Vitest 3, @astrojs/check, ESLint 9 + Prettier, GitHub Actions.

**Rama:** `mejoras/2026-09`, un commit por tarea. Convención: Conventional Commits en español como el historial.

**Compatibilidad:** el código debe funcionar antes y después de aplicar las migraciones (expand → migrate → contract). Antes de aplicarlas: no hay Realtime y `current_amount` lo recalcula el servidor al confirmar. Después: el trigger lo mantiene y Realtime vuelve.
